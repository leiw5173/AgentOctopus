Add a native Windows restricted sandbox backend (`WinSandboxBackend`) for hosts without WSL2/Hyper-V/Docker Desktop. It delivers honest `restricted`-level **process isolation** (not AppContainer capability isolation) by layering user-mode Windows primitives — Job Object limits (`KILL_ON_JOB_CLOSE`), a `CreateRestrictedToken`-hardened token at Low Integrity Level (privileges stripped, Administrators deny-only), and a persistent WFP egress allowlist (permits only the loopback proxy, scoped to the sandbox `node.exe` application ID) — enforced by a privileged `OctopusSandboxGate` companion service over a strictly-ACL'd named-pipe RPC. The LPAC/AppContainer token is not used on the execution path: it is the confirmed necessary trigger of the Node launch crash, so Node cannot run under it; the LPAC path is retained only as a diagnostic probe. Selection is opt-in only via a new `defaultBackend:'windows'` + `minIsolationLevel:'restricted'` pair; a new `windowsRuntime { manifestPath, nodePath, bootstrapPath }` profile block carries the verified Node runtime. The runner gains a `windows` branch in the runtime↔backend cross-check and registers the backend in both default factory builders. Never claims `full` isolation; `auto` never selects it.
