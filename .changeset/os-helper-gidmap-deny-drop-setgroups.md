os-helper: keep the phase-1 `/proc/self/setgroups` "deny" write mandatory and DROP the phase-3 `setgroups(0, NULL)` call. On the privileged runner the helper's `gid_map` write EPERMs while its `uid_map` write succeeds — the `user_namespaces(7)` signature of a missing `CAP_SETGID` in the PARENT user namespace (the runner's uid-0 process has a restricted capability bounding set: `CAP_SETUID` present, `CAP_SETGID` absent). The only `gid_map` path for a writer without parent-ns `CAP_SETGID` is the kernel's unprivileged self-map fallback, which UNCONDITIONALLY requires `setgroups` to be "deny" first — there is no write order that avoids it (the capability is checked against the parent namespace regardless of `uid_map` state, per `new_idmap_permitted()`). "deny" is a per-userns, IRREVERSIBLE flag (`USERNS_SETGROUPS_ALLOWED`) that permanently disables `setgroups(2)` for the whole namespace, so the phase-3 `setgroups(0, NULL)` would EPERM. That call is removed: it is a no-op on the runner (real gid 0, no supplementary groups), and `setgid()`/`setuid()` are unaffected by "deny". An earlier root-only "deny" skip is reverted — it let `gid_map` EPERM.
